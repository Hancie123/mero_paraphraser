# Mero Paraphraser

An offline desktop paraphrasing tool built with **Tauri 2** (Rust + React/TypeScript UI) and a rule-based **Python** engine.

## Features

- One mode, **Humanize**: natural, human-sounding rewording that keeps the meaning
- A "Changes" slider that controls how much text is rewritten
- An eight-layer pipeline that protects citations, quotations and references, checks that the facts didn't change, and explains what it changed (the **Review** tab)
- Changed words are highlighted. Click one to pick another alternative or go back to the original.
- **Section-aware**: Abstract, Introduction, Discussion and Conclusion are rewritten; code blocks, tables, equations, headings and sections such as Declarations, Funding, Conflicts of interest, Data availability and Keywords are kept exactly as written
- **Code-safe**: in code blocks only natural-language comments (`#`, `//`, `/* */`, `--`, Python docstrings) are reworded. The block is lexed again afterwards and every code token must be identical (for Python the syntax tree too); otherwise the block is left unchanged. Directives (`# noqa`, `// @ts-ignore`, licence headers), doctests and unknown languages are never touched
- **Plainer wording**: stock language-model phrases ("delve into", "plays a pivotal role", "a myriad of") are replaced wherever they appear, and em dashes become commas, colons or full stops
- **Invisible-character cleanup**: zero-width spaces, word joiners, BOMs, soft hyphens, stray bidi controls and hidden tag characters are removed, while the joiners Nepali, Hindi, Arabic and emoji need are kept
- **Word files**: open a .docx, save the result as a .docx that carries no document properties (no author, company, timestamps or revision IDs), and *File > Remove personal info from a Word file* to strip names, dates, revision IDs, custom properties and template paths from an existing document
- Runs fully offline and fast. The engine uses only the Python standard library, with no AI model to download.

- `src-tauri/src/engine.rs` starts the engine on demand, restarts it if it crashes, and stops it on exit.
- `src/` is the React UI.

In **dev** the app runs `python-engine/app/main.py` with your system Python (set `MERO_PYTHON` to use a different interpreter).
In **release** the engine is bundled with PyInstaller and shipped as a Tauri sidecar, so users don't need Python installed.

## The eight layers

| # | Layer | What it does |
|---|---|---|
| 1 | Input processing | Cleans invisible characters and line endings, finds sections, code, tables and math (`sections.py`), splits paragraphs, sets a trailing reference list aside, and replaces citations (`(Smith, 2020)`, `Smith et al. (2020)`, `[3]`), direct quotations, links, DOIs and code with `[[n]]` tokens |
| 2 | Context analysis | Detects the register (academic, professional, general), proper names and acronyms, repeated key terms, and logical relationships (contrast, cause and effect…) |
| 3 | Semantic understanding | Lists what each part must keep: numbers, names, negations and hedges ("may", "suggests") |
| 4 | Rewriting | Rewrites a few paragraphs at a time with the rule-based engine: phrase rewrites, synonym swaps and contractions. It writes 2–3 drafts with different seeds and keeps the one that reads most human |
| 5 | Language refinement | Fixes spacing, punctuation, doubled words, sentence capitals and "a"/"an"; replaces stock AI phrases the author didn't use and AI-favoured words ("utilize", "delve into", "foster") everywhere; and breaks up structures detectors flag (see below) |
| 6 | Meaning validation | Checks that the numbers, names, negations and hedges from layer 3 are still there, and that the length didn't change too much |
| 7 | Citation validation | Every token must come back exactly once and no new citations may appear; on the final text, every citation, quotation and the reference list must be verbatim |
| 8 | Final output | Highlights each change with its kind (synonym, reworded…), and builds the per-layer report and explanations shown in the Review tab |

A part that fails layer 6 or 7 is rewritten once more with new wording. If its citations still can't be preserved, it is kept unchanged.

## Human-like output

AI detectors such as GPTZero measure how predictable the wording is, how much sentence length varies (burstiness), and structures models overuse. `app/pipeline/humanizer.py` works against the last two:

- **Drafts.** Layer 4 writes 2 drafts (3 at moderate or strong changes). After Layers 5–7, drafts are ranked by problems found, then by sentence-length variation and AI patterns found.
- **Structure (Layer 5).** Without changing meaning, it removes summary openers ("Overall,") and an added closing summary sentence, unrolls "not only… but also", swaps stiff connectors for natural ones with the same meaning ("Furthermore," → "On top of that,"; "However," → "That said,"), merges "X. This shows Y" into "X, which shows Y", drops inferable words ("If it is possible" → "If possible"), and splits a long sentence when lengths are too even. It also uses contractions, sentences starting with "But"/"So", at most one em dash, and an occasional parenthetical aside.
- **Academic text.** When Layer 2 detects academic writing, precise words such as "robust" are kept.

What it deliberately does **not** do: invent anecdotes, examples, data or opinions, add or remove hedging, insert slang, or add grammar mistakes or hidden characters. Layers 3 and 6 reject anything that changes facts. The Review tab's Final output report lists any AI-like structures that remain, and `report.humanness` holds the scores.

**Measuring.** `python python-engine/tools/eval_humanness.py` runs `tools/samples/*.txt` through the pipeline and prints burstiness, patterns, the human score and the fact-check pass rate. With `GPTZERO_API_KEY` set, it also asks GPTZero (a paid API that sends the text to GPTZero). Re-run it after GPTZero updates, not only after code changes.

**Synonyms.** The rule engine uses the hand-written groups in `app/core/lexicon.py`. The editor's word suggestions also offer about 330 adjectives and adverbs from `app/data/synonyms_extra.json`, which `tools/build_lexicon.py` builds from WordNet and word frequencies (`pip install -r python-engine/tools/requirements-build.txt` first; the engine reads the JSON with the standard library). To drop a bad pair, add it to `EXCLUDE` or `_BAD` in the script and run it again.

## Requirements

Node 20+, pnpm, Rust (stable), Python 3.10+

## Development

```bash
pnpm install
pnpm tauri:dev
```

Test the engine on its own:

```bash
pnpm test:engine
python python-engine/app/main.py --report --text "I don't think it's a big problem."
```

## Release build

```bash
python -m pip install -r python-engine/requirements.txt   # once (PyInstaller)
pnpm tauri:build
```

`tauri:build` does two things:

1. `scripts/build-engine.mjs` builds the engine into `src-tauri/binaries/mero-paraphraser-engine-<target-triple>`.
2. `tauri build` runs with `src-tauri/tauri.bundle.json`, which adds the engine sidecar and builds the NSIS installer in `src-tauri/target/release/bundle/nsis/`. The installer is the whole release.

## Customizing

- **Vocabulary:** add synonym groups to `GROUPS` in `python-engine/app/core/lexicon.py`. Use `keys` to list only the words that are safe to replace. If a word is ambiguous (for example "show" can be a noun), list it only as a replacement. Run `pnpm test:engine` after editing; it catches duplicate keys.
- **Phrases:** `GENERAL_PHRASES` and `CONTRACT_PHRASES` in the same file control phrase rewrites and contractions.
