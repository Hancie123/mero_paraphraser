# Mero Paraphraser

An offline desktop paraphrasing tool built with **Tauri 2** (Rust + React/TypeScript UI) and a **Python** engine that runs a local AI model.

## Features

- Seven modes: **Standard**, **Academic**, **Professional**, **Fluent**, **Simple**, **Creative**, **Shorten**
- A "Changes" slider that controls how much text is rewritten
- An eight-layer pipeline that protects citations, quotations and references, checks that the meaning didn't change, and explains what it changed (the **Review** tab)
- Changed words are highlighted. Click one to pick another alternative or go back to the original.
- Offline AI model (Qwen3 4B Instruct, Apache 2.0). A rule-based engine is used until the model is installed.
- Runs fully offline. The engine uses only the Python standard library.

- `src-tauri/src/engine.rs` starts the engine on demand, restarts it if it crashes, and stops it on exit.
- `src/` is the React UI.

In **dev** the app runs `python-engine/app/main.py` with your system Python (set `MERO_PYTHON` to use a different interpreter).
In **release** the engine is bundled with PyInstaller and shipped as a Tauri sidecar, so users don't need Python installed.

## The eight layers

| # | Layer | What it does |
|---|---|---|
| 1 | Input processing | Cleans invisible characters and line endings, splits paragraphs, sets a trailing reference list aside, and replaces citations (`(Smith, 2020)`, `Smith et al. (2020)`, `[3]`), direct quotations, links, DOIs and code with `[[n]]` tokens |
| 2 | Context analysis | Detects the register (academic, professional, general), proper names and acronyms, repeated key terms, and logical relationships (contrast, cause and effect…) |
| 3 | Semantic understanding | Lists what each part must keep: numbers, names, negations and hedges ("may", "suggests") |
| 4 | AI rewriting | Rewrites a few paragraphs at a time with the mode's prompt plus what layers 2 and 3 found. It writes 2–3 drafts at once and keeps the one that reads most human (see below). While generating, a `logit_bias` discourages AI-typical words ("delve", "moreover", "tapestry"…) unless the author used them, DRY discourages repeated phrasing, and XTC (Standard, Fluent and Creative only) varies word choice. See `SAMPLING`, `HUMAN_SAMPLING` and `AVOID_WORDS` in `app/core/config.py` |
| 5 | Language refinement | Fixes spacing, punctuation, doubled words, sentence capitals and "a"/"an"; replaces stock AI phrases the author didn't use and AI-favoured words ("utilize", "delve into", "foster") everywhere; and breaks up structures detectors flag (see below) |
| 6 | Meaning validation | Checks the facts from layer 3, then has the model list added, missing or changed details and score the rewrite from 1 to 5 |
| 7 | Citation validation | Every token must come back exactly once and no new citations may appear; on the final text, every citation, quotation and the reference list must be verbatim |
| 8 | Final output | Highlights each change with its kind (synonym, reworded, shortened…), and builds the per-layer report and explanations shown in the Review tab |

A part that fails layer 6 or 7 is rewritten once more with the problems as feedback. If its citations still can't be preserved, it is kept unchanged. Layers 2, 3 and 5 are rule-based on purpose, because each extra model call costs several seconds on a CPU. Expect roughly 25–60 seconds per few paragraphs on a typical laptop CPU, including validation and the extra drafts.

The meaning check (layer 6) runs on the same 4B model. It catches most changes in meaning, but not all of them, so review the result for anything important.

## Human-like output

AI detectors such as GPTZero mainly measure **perplexity** (how predictable each word is to a language model) and **burstiness** (how much that, and sentence length, vary), plus structures models overuse. `app/pipeline/humanizer.py` works against all three:

- **Drafts, scored by the model.** Layer 4 writes 2 drafts (3 at moderate or strong changes) in parallel. llama-server runs `PARALLEL` slots with one shared KV cache, so 3 drafts cost only a few seconds more than one on a CPU. Each draft comes back with the model's own token probabilities. After Layer 5 and the cheap checks, drafts are ranked by surprisal, how much it varies between sentences, sentence-length variation, and AI patterns found. Only the best ones go to the slow meaning check.
- **Less predictable sampling.** `HUMAN_SAMPLING` replaces top-k/top-p, which cut off every less likely word, with `min_p` and dynamic temperature (cooler when the model is sure, such as names, numbers and `[[n]]` tokens).
- **Polish.** The winning draft gets one sentence rewritten: one that starts like the sentence before it, otherwise the most predictable one. A few predictable adjectives and adverbs are also swapped for lexicon synonyms, but only synonyms the model itself rated likely in that spot, so the swap fits the context and register. Verbs and nouns are never swapped, because that breaks grammar.
- **Structure (Layer 5).** Without changing meaning, it removes summary openers ("Overall,") and a closing summary sentence the model added, unrolls "not only… but also", swaps stiff connectors for natural ones with the same meaning ("Furthermore," → "On top of that,"; "However," → "That said,"), merges "X. This shows Y" into "X, which shows Y", drops inferable words ("If it is possible" → "If possible"), and splits a long sentence when lengths are too even. Casual modes also get contractions, sentences starting with "But"/"So", at most one em dash, and an occasional parenthetical aside. Creative may set a short takeaway on its own line.
- **Prompts.** `system.txt` bans the usual tropes (formulaic hooks, buzzwords, sentences that all start the same way, restating the point). `fluent.txt` and `creative.txt` allow fragments for emphasis, everyday expressions next to precise ones, and lists that aren't perfectly parallel.

What it deliberately does **not** do: invent anecdotes, examples, data or opinions, add or remove hedging, insert slang the source didn't use, or add grammar mistakes or hidden characters. Layers 3 and 6 reject anything that adds or changes facts, and a paraphraser that slips made-up details into someone's essay or report causes real harm. The Review tab's Final output report lists any AI-like structures that remain, and `report.humanness` holds the scores.

**Your own voice.** Put samples of real human writing (ideally the user's own) in `%LOCALAPPDATA%\com.merovision.paraphraser\style\` as `<mode>.txt` (for example `academic.txt`) or `all.txt`. The rewrite prompt includes them as a style reference. An `avoid.txt` in the same folder adds words to discourage, one per line (`synergize` or `beacon -20`). `MERO_STYLE_DIR` points to another folder.

**Measuring.** `python python-engine/tools/eval_humanness.py --modes standard academic` runs `tools/samples/*.txt` through the pipeline and prints burstiness, patterns, the human score and the meaning pass rate. With `GPTZERO_API_KEY` set, it also asks GPTZero (a paid API that sends the text to GPTZero). Re-run it after GPTZero updates, not only after code changes.

**Synonyms.** Word swaps use the hand-written groups in `app/core/lexicon.py` plus about 330 adjectives and adverbs in `app/data/synonyms_extra.json`, which `tools/build_lexicon.py` builds from WordNet and word frequencies (`pip install -r python-engine/tools/requirements-build.txt` first; the engine reads the JSON with the standard library). Generated words are used only where something else checks the context: the humanizer swaps one only if the model rated it likely at that spot, and the editor offers them as suggestions. The offline rule engine ignores them. To drop a bad pair, add it to `EXCLUDE` or `_BAD` in the script and run it again.

**Fine-tuning.** With `MERO_COLLECT_PREFS=<file.jsonl>` set, every part with several drafts saves a (shipped, least-human) pair. `tools/train_dpo.py` trains a LoRA on those pairs with DPO, so the model writes this way by default. Its `--help` covers GPU needs, conversion to GGUF and how to try the result.

Settings (`app/core/config.py`): `drafts_for` (or `MERO_DRAFTS=1..3`), `HUMAN_SAMPLING`, `SWAP_RATE`, `SWAP_MIN_PROB`, `MAX_SWAPS`, `FLAT_SENTENCE`, `CASUAL_MODES`.

## AI model

The model and runtime are two pinned, SHA-256-verified files, about 2.5 GB in total, stored in `%LOCALAPPDATA%\com.merovision.paraphraser\ai`. The uninstaller's "Delete the application data" option removes that folder.

How the model gets there:

- **Release:** `pnpm tauri:build` creates `release/Mero Paraphraser <version>/` containing the installer and an `ai\` folder. The post-install hook in `src-tauri/windows/hooks.nsh` copies `ai\` into the data folder, so installation works offline. Zip and ship the whole folder. The model can't be put inside the installer because NSIS installers are limited to 2 GB.
- **Otherwise** (development, or running the installer without the `ai\` folder): the app downloads the model automatically on first launch and uses the rule-based engine until the download finishes.
- **Development:** a model placed at `python-engine/models/model.gguf` is used instead of the installed one.

`llama-server` runs on a random localhost port and is placed in a Windows job object, so it is closed even if the engine is killed.

Overrides: `MERO_AI_HOME` (data folder), `MERO_LLAMA_SERVER` (path to `llama-server`) and `MERO_AI_MODEL` (path to a `.gguf`).

To upgrade the model or runtime, change `RUNTIME` / `MODEL` in `app/core/config.py`. Update the URL, SHA-256 and size together, and update `MERO_AI_MODEL_FILE` in `hooks.nsh`.

Node 20+, pnpm, Rust (stable), Python 3.10+

## Development

```bash
pnpm install
pnpm tauri:dev
```

Test the engine on its own:

```bash
pnpm test:engine
python python-engine/app/main.py --prepare-ai      # download and verify the model
python python-engine/app/main.py --engine ai --mode academic --report --text "I don't think it's a big problem."
```

## Release build

```bash
python -m pip install -r python-engine/requirements.txt   # once (PyInstaller)
pnpm tauri:build
```

`tauri:build` does three things:

1. `scripts/build-engine.mjs` builds the engine, with its prompt files, into `src-tauri/binaries/mero-paraphraser-engine-<target-triple>`.
2. `tauri build` runs with `src-tauri/tauri.bundle.json`, which adds the engine sidecar and builds the NSIS installer.
3. `scripts/package-release.mjs` assembles `release/Mero Paraphraser <version>/` with the installer and the AI model.

## Customizing

- **Prompts:** edit the files in `python-engine/app/prompts/`. `system.txt` holds the rules for every rewrite, `judge.txt` is the meaning check, and each mode has its own file.
- **Rule-based vocabulary:** add synonym groups to `GROUPS` in `python-engine/app/core/lexicon.py`. Use `keys` to list only the words that are safe to replace. If a word is ambiguous (for example "show" can be a noun), list it only as a replacement. Run `pnpm test:engine` after editing; it catches duplicate keys.
